# Expense Tracker: Build Plan

This document is a complete specification for building the Expense Tracker from scratch. It is derived from the reference application in this repository and keeps its behavior, except where **Fix in rebuild** says otherwise. Follow it in order. Where this plan and the reference code disagree, this plan wins.

The app is a single-user, password-gated personal finance tracker. It records expenses, income, donations, and money lent; splits shared expenses; tracks who owes money back; and compares monthly spending to a monthly budget. Currency is Indian rupees (`₹`).

## 2. shadcn/ui Rules (mandatory)

1. **Initialize shadcn/ui first** with the current CLI, which targets Tailwind 4 and React 19: `npx shadcn@latest init`. Settings: base color `slate`, CSS variables `yes`. In `components.json`: `"rsc": false`, `"tsx": true`, `"tailwind": { "config": "", "css": "app/globals.css", "baseColor": "slate", "cssVariables": true }`, aliases `components` → `@/components`, `ui` → `@/components/ui`, `utils` → `@/lib/utils`, `lib` → `@/lib`, `hooks` → `@/lib/hooks`, `iconLibrary` → `lucide`. Empty `tailwind.config` is correct for Tailwind 4. Init writes the tokens and `@theme inline` block into `app/globals.css`.
2. **Add primitives with the CLI** (`npx shadcn@latest add <name>`). They live in `components/ui/`. Do not hand-write a primitive that shadcn provides.
3. **Never build custom versions of** buttons, inputs, selects, checkboxes, switches, modals, dropdowns, popovers, comboboxes, tooltips, tables, cards, badges, progress bars, skeletons, alerts, or toasts. Compose the shadcn ones.
4. **Feature components** (`components/expenses/*`, `components/budget/*`, etc.) contain only composition, layout, and app logic. They import from `@/components/ui/*`.
5. **Edit `components/ui/*` only to add variants** (via `cva`) or to fix a bug. Keep edits minimal and note them in a comment.
6. **Style with tokens:** `bg-background`, `text-foreground`, `bg-card`, `text-muted-foreground`, `border`, `bg-primary`, `text-destructive`, and the app tokens from section 1.5 (`text-expense`, `bg-income/10`, ...). Dark mode then works without `dark:` overrides. Use `dark:` only when a token genuinely cannot express the difference.
7. **Reusable composites** that appear more than once go in `components/shared/` (e.g. `Combobox`, `MultiSelect`, `MonthPicker`, `ConfirmDialog`, `Money`). Build them once from shadcn primitives and reuse them.

## 3. UX Requirements

- **Layout:** max width `1600px`, centered. Header: title "Expense Tracker", subtitle "Manage your monthly expenses", right side theme switcher + Logout button. Below `lg`: single column, summary under the table. At `lg`+: 3-column grid, table spans 2, summary spans 1 and is `sticky top-4`.
- **Mobile first:** 16px side gutter, no horizontal page scroll (the table itself may scroll horizontally inside its container). Hide Payment Mode column below `md` and Payment Status column below `lg`. Touch targets ≥ 40px. Forms open as a `Drawer` on mobile.
- **Viewport:** `width=device-width, initialScale=1, maximumScale=1, userScalable=false`, theme color `#4f46e5`.
- **Keyboard:** all dialogs close on `Escape` and trap focus (built into Radix). Comboboxes support arrow keys and Enter. Every interactive element is reachable by Tab and has a visible focus ring.
- **Accessibility:** WCAG 2.1 AA contrast in both themes. Every input has a `Label`. Icon-only buttons have `aria-label` or `sr-only` text. Offline banner uses `role="alert"`.
- **Feedback:**
  - Submit buttons show a spinner (`Loader2` with `animate-spin`) and are disabled while the write is in flight. Close the dialog only after the write succeeds.
  - Success: brief toast ("Transaction added", "Budget saved", etc.).
  - Failure: error toast with a readable message. Map Firestore codes: `permission-denied` → "Permission denied. Check Firestore security rules."; `unavailable` → "Firestore is unavailable."; `failed-precondition` → "Firestore index required."; others → the error message.
- **Loading:** skeletons for table and summary while initial data loads. No layout shift when data arrives.
- **Empty states:**
  - No transactions at all: icon, "No expenses yet", "Add your first transaction" button.
  - Filters match nothing: `Search` icon, "No expenses match your filters", "Clear filters" button.
- **Dynamic labels:** title field label and person field label/placeholder change with transaction type:
  - Expense: "Expense Title", "For Whom", placeholder "Self or person's name".
  - Income: "Income Title", "From Whom", placeholder "Person's name".
  - Donation: "Donation Title", "For Whom", placeholder "Self, organization or person's name".
  - Lent: "Money Lent Title", "To Whom", placeholder "Person's name".
  - Payment received checkbox label: Lent → "Money received back from {name}", otherwise "Payment received from {name}".
- **Money format:** `₹` + `formatNumber(value)`: comma grouping, two decimals, trailing `.00` removed. Implement once as `shared/Money`.

## 5. Data Model (Firestore)

### 5.1 Collections

- `expenses`: every transaction, any type.
- `budgets`: one document per month.

There is no user ID field. The app is single-user.

### 5.2 Types

```ts
// types/expense.ts
export type PaymentMode = 'Credit Card' | 'Debit Card' | 'UPI' | 'Cash';
export type TransactionType = 'expense' | 'income' | 'donation' | 'lent';

export interface SplitDetail {
  person: string;              // 'Self' or a name
  amount: number;
  paymentReceived?: boolean;
  paymentReceivedDate?: Date;
}

export interface Expense {
  id: string;
  title: string;
  amount: number;
  paymentMode: PaymentMode;
  forWhom: string;             // 'Self', a name, or 'Split' when isSplit
  date: Date;
  transactionType?: TransactionType; // missing → 'expense'
  paymentReceived?: boolean;
  paymentReceivedDate?: Date;
  isSplit?: boolean;
  splitDetails?: SplitDetail[];
  category?: string;
}

// types/budget.ts
export interface Budget {
  id: string;
  month: Date;                 // first day of month, local time
  amount: number;
  createdAt: Date;
  updatedAt: Date;
}
```

### 5.3 Stored document shape

`expenses/{id}`:

| Field | Type | Rule |
|---|---|---|
| `title` | string | trimmed |
| `amount` | number | > 0 |
| `paymentMode` | string | one of `PaymentMode` |
| `forWhom` | string | `Self`, a name, or `Split` |
| `date` | Timestamp | |
| `transactionType` | string | always written |
| `paymentReceived` | boolean | always written (false when not applicable) |
| `paymentReceivedDate` | Timestamp \| null | |
| `isSplit` | boolean | always written |
| `splitDetails` | array \| null | each `{ person, amount, paymentReceived, paymentReceivedDate: Timestamp \| null }` |
| `category` | string \| null | trimmed, null when empty |

`budgets/{id}`: `month` (Timestamp, first day of month), `amount` (number), `createdAt`, `updatedAt` (Timestamps).

### 5.4 Reading

- Load the whole collection: `expenses` ordered by `date desc`, `budgets` ordered by `month desc`.
- Convert Timestamps to `Date`. Apply defaults on read: `transactionType ?? 'expense'`, `paymentReceived ?? false`, `isSplit ?? false`, split `paymentReceived ?? false`, `category || undefined`.
- Normalize `forWhom` and split `person` on read with `normalizePerson` (section 7.1) so legacy lowercase `self` works.
- Use Firestore `withConverter` in the repositories for this mapping.

### 5.5 Firestore rules (parity with reference)

The browser talks to Firestore directly and the app does not use Firebase Auth, so rules cannot tell logged-in users apart. Ship these rules and document the limitation in `FIRESTORE_SETUP.md`:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /expenses/{doc} { allow read, write: if true; }
    match /budgets/{doc}  { allow read, write: if true; }
  }
}
```

The reference setup guide only covers `expenses`; the rebuild must include `budgets`. **Known limitation:** the login cookie gates the UI, not the data. Anyone with the Firebase config can read and write. Do not claim otherwise in docs.

## 6. Authentication

### 6.1 Flow

- `/login` page: `Card` with username `Input`, password `Input type=password`, submit `Button`, inline error text, theme switcher, offline banner.
  - On mount, `GET /api/auth/check`; if `{ authenticated: true }`, redirect.
  - On submit, `POST /api/auth/login` with `{ username, password }`. On 200, `router.replace(from ?? '/')` then `router.refresh()`. On error, show `error` from the response or "Invalid username or password".
- Logout button: `POST /api/auth/logout`, then `window.location.href = '/login'`. Disable the button and show "Logging out..." while pending.

### 6.2 Route handlers

Next 15: `cookies()` from `next/headers` is async; always `await cookies()`. Route handlers are not cached by default.

- `POST /api/auth/login`: 400 if username or password missing; 401 if credentials invalid; otherwise set cookie and return `{ success: true }`. 500 on unexpected error.
- `POST /api/auth/logout`: clear cookie (`maxAge: 0`, same attributes), return `{ success: true }`.
- `GET /api/auth/check`: `{ authenticated: boolean }`, always status 200.

### 6.3 Credentials

`validateCredentials(username, password)` compares against `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD`. If either env var is missing: accept any credentials when `NODE_ENV !== 'production'`; in production reject all logins and log an error. (**Fix in rebuild:** the reference accepts anything in production too.)

### 6.4 Session cookie

- Name `auth-session`. `httpOnly`, `sameSite: 'lax'`, `secure` in production, `path: '/'`, `maxAge` 7 days.
- Value: HS256 JWT signed with `SESSION_SECRET` via `jose`, `exp` = now + 7 days. (**Fix in rebuild:** the reference uses unsigned base64 `timestamp-random`, which anyone can forge.)
- Verify with `jwtVerify` in middleware and in `/api/auth/check`.

### 6.5 Middleware

- Matcher: `/((?!_next/static|_next/image|favicon.ico|manifest.json|icons/).*)` (do **not** exclude `/api`).
- Allow without session: `/login`, `/api/auth/*`, `/manifest.json`, `/icons/*`.
- Any other page with a missing/invalid session → redirect to `/login?from=<pathname>`. Any other `/api/*` request without a session → 401 JSON.
- **Fix in rebuild:** the login page must honor `from` (only if it starts with `/` and not `//`).

## 7. Features

### 7.1 Shared domain helpers

- `normalizePerson(s)`: trim; if lowercase equals `self`, return `'Self'`.
- `isSelf(s)`: `normalizePerson(s) === 'Self'`. Use everywhere instead of `=== 'Self'`.
- `canHavePaymentStatus(e)`: not split, not self, and type is `expense`, `donation`, or `lent`.
- Dates (`lib/dates.ts`): form dates are calendar dates. Parse `yyyy-MM-dd` as **local** midnight (`parse(value, 'yyyy-MM-dd', new Date())`) and format with `format(date, 'yyyy-MM-dd')`. Default to today in local time. (**Fix in rebuild:** the reference uses `toISOString()` and `new Date('yyyy-MM-dd')`, which use UTC and can shift the day.)

### 7.2 Dashboard state (`app/page.tsx`)

- On mount, load expenses and budgets in parallel. When connectivity goes from offline to online, reload both.
- State: `expenses`, `budgets`, `currentMonth` (default today), filter selections (section 7.3), dialog open states, editing targets, loading flags.
- `currentBudget` = budget whose `startOfMonth(month)` equals `startOfMonth(currentMonth)`.
- Person suggestions: unique sorted `forWhom` values from loaded expenses, excluding `Split`, with `Self` first. Category suggestions: unique sorted non-empty categories.
- After every successful mutation, reload the affected collection.

### 7.3 Filters

Filter state: `paymentModes: PaymentMode[] | 'All'`, `persons: string[] | 'All'`, `types: TransactionType[] | 'All'`, `paymentStatus: 'All' | 'Received' | 'Pending'`, `categories: string[] | 'All'`. All default to `'All'`.

`applyFilters(expenses, month, filters)` in `lib/filters.ts`, applied in order:

1. Date within `startOfMonth(month)`..`endOfMonth(month)`.
2. Type in selected types (missing type = `expense`).
3. Payment mode in selected modes.
4. `forWhom` in selected persons.
5. Payment status (when not `All`):
   - Regular transactions: keep only if `canHavePaymentStatus(e)` and `paymentReceived` matches.
   - Split expenses: derive status from non-self shares. "Received" = all non-self shares received; "Pending" = at least one not received.
   - Everything else is excluded.
   - (**Fix in rebuild:** the reference excludes donations, and always treats split parents as Pending.)
6. Category: keep only if category is non-empty and selected.

Filters sheet contains: month picker, transaction type multi-select, payment mode multi-select, person multi-select, payment status select, category multi-select, and a footer with "Clear all" and "Done". Filters apply live.

`hasActiveFilters` = any filter not `All`, or `currentMonth` not the current calendar month. "Clear filters" resets every filter to `All` and `currentMonth` to today. Show a "Clear filters" button in the list header when filters are active and in the no-match empty state. Show an active-filter count `Badge` on the Filters button.

`MonthlySummary` receives **all** expenses and applies only the month. Filters never change the summary.

### 7.4 Transaction form

Zod schema (`lib/validation/expense.ts`):

- `transactionType`: enum, default `expense`.
- `title`: trimmed, required.
- `amount`: number > 0, two decimals max. (**Fix in rebuild:** the reference accepts zero/negative.)
- `paymentMode`: enum, default `Credit Card`.
- `date`: required.
- `forWhom`: required unless split. Default `Self`.
- `category`: optional, trimmed.
- `isSplit`: only allowed when type is `expense`.
- `splitDetails` (when split):
  - At least 2 rows.
  - Every name non-empty.
  - Names unique, ignoring case.
  - Exactly one row is `Self`, ignoring case.
  - Amounts ≥ 0.
  - `|sum − amount| ≤ 0.01`, with message `Total amount (₹X) does not match sum of splits (₹Y).`
- `transactionType === 'lent'` → `forWhom` cannot be `Self`: "Money Lent transactions cannot be for "Self". Please enter a person's name." Also hide `Self` from suggestions for lent.
- `paymentReceived`: only shown and saved when `canHavePaymentStatus` holds for the form values.

Split editor behavior:

- Turning split on (expense only): start with rows `Self` and an empty row. If amount is set, divide it equally, with the last row taking the remainder.
- The last row's amount is auto-calculated as `max(0, amount − sum(other rows))` whenever the total or another row changes.
- Add row button; remove row button disabled when only 2 rows remain.
- Name combobox suggests `Self` + known persons, excluding names already used in other rows. A second `Self` cannot be entered.
- Turning split off when split rows have data asks for confirmation ("Converting to regular transaction will lose split details. Continue?") via `ConfirmDialog`, then resets rows.
- Each non-self split row shows a "received" `Checkbox` when editing.

On submit, build the payload:

- Normalize `forWhom` (`Split` when split).
- Normalize split person names.
- `paymentReceived` = value if applicable, else false.
- `paymentReceivedDate`:
  - Unchecked → none.
  - Checked and it was already received on the edited record → keep the existing date.
  - Otherwise → now. (**Fix in rebuild:** the reference overwrites the date on every edit.)
- Same rule for each split row's `paymentReceivedDate`.
- `category` trimmed or omitted.

Editing pre-fills every field. After a successful create, reset the form.

## 8. Accounting Rules (`lib/accounting.ts`)

Pure functions, unit-tested. Input is all expenses and a month; first keep transactions within that month. Let `type = transactionType ?? 'expense'`.

| Name | Definition |
|---|---|
| `selfExpenses` | type `expense`, not split, `isSelf(forWhom)` |
| `otherExpenses` | type `expense`, not split, not self |
| `splitExpenses` | type `expense`, `isSplit` with `splitDetails` |
| `totalSpentByMe` | Σ selfExpenses.amount + Σ Self share of each split |
| `totalSpentForOthers` | Σ otherExpenses.amount + Σ non-self shares of splits |
| `othersReceived` / `othersPending` | Σ otherExpenses.amount where `paymentReceived` true / false |
| `totalIncome` | Σ amount, type `income` |
| `totalDonations` | Σ amount, type `donation` |
| `selfDonations` | Σ amount, type `donation`, self |
| `pendingDonations` | Σ amount, type `donation`, not self, not received |
| `totalLent`, `lentReceived`, `lentPending` | Σ amount, type `lent`: all / received / not received |
| `pendingSplitShares` | Σ non-self split shares not received |
| `netAmount` | `totalSpentByMe + selfDonations + pendingDonations + othersPending + pendingSplitShares + lentPending − totalIncome` |
| budget | `remaining = budget − netAmount`; `percentage = netAmount / budget × 100` (bar capped at 100) |
| `moneyToCollect` | group by person: pending otherExpenses, pending non-self split shares (with split index), pending non-self donations, pending lent. Each group: `{ person, amount, count, items }`. Items sorted by date desc, groups by amount desc. |
| `listTotal(rows)` | Σ type `expense` + Σ type `lent` − Σ type `income` |

**Fix in rebuild:** the reference `netAmount` omits `pendingSplitShares`, even though those shares appear in Money to Collect. Including them makes "pending money owed to me" count the same way whether it came from a regular expense or a split.

Required unit tests:

- Each formula above.
- Legacy lowercase `self`.
- Missing `transactionType`.
- Split with partial receipts.
- Month boundaries (first and last day, local time).
- Empty month.
